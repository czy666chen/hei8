## 3. 关键判断

### 3.1 “当前没有可见手牌”的可能根因

这不应先按纯样式处理。按当前模型，出现该提示有三类可能：

1. **正常投影为空**：注册玩家正在看未认领临时席位，或成员还没有绑定到对应 player seat。此时服务端会把该席位 `hands[playerId]` 投影为空。
2. **新一轮重发丢失手牌**：`redealRoomCards` 只遍历 `Object.keys(cards.hands)`；如果某轮前 `hands` 键集合丢失，或 `pendingHandSizes[playerId]` 被置为 0，新一轮后会真实发 0 张。
3. **前端错误展示全部席位**：非房主视图仍渲染所有玩家的卡牌栏，导致看到其他人的空投影并误以为“自己没有牌”。

本轮必须先通过测试/日志确定是哪一类，再改 UI。

### 3.2 认领席位的产品口径

认领不应再依赖“先点计分板某玩家”这种隐式操作。房主应能在每个成员（包括自己）旁边选择要绑定的局内玩家：

- 认领目标 = 明确选择的未绑定 seat/player。
- 房主成员也显示同样的认领控件。
- 已绑定席位不可重复认领，除非后续另做“解除绑定/转移绑定”功能。
- 认领成功后计分板当前选中项同步到该席位。

## 7. 明确不做

- 不改变实时房间后端权限模型：观战者仍只读，注册玩家只操作本人绑定席位，房主有全局权限。
- 不在本轮加入“解除认领 / 转移认领”的完整流程；本轮只解决“认领到哪个玩家”的显式选择。
- 不重做普通计分板或普通中八页面，只把实时房间对齐它们的尺寸和主题规则。
- 不把截图中的界面文字当作新业务规则；截图只用于定位 UI 问题。
